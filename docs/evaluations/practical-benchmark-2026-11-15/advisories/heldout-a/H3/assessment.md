- **Property/domain:** proposed initial count-only domain: max in {1,2,3}, finite keys {a,b,c,d}, nonundefined primitive values {1,2}, operation sequences of length 0–8 over set/get/delete/clear including set(k,undefined), repeated equal-value set, absent delete/get, deletion of head/tail/interior, singleton clear/delete and reinsertion after a freed slot. Preconditions: fresh valid count-only cache; ttl/maxSize/maxEntrySize zero; no size options, fetch/memo/disposal/insert hooks, diagnostic subscribers or external mutation/reentrancy. This is explicitly a proposed bounded configuration, not supported arbitrary-code verification. Abstract invariant: ordered live keys contain no duplicates, length <=max and equals reported size; values match the oracle. Proposed correspondence invariant: map indices bijectively identify live slots, following next from head reaches each live index exactly once to tail, adjacent live next/prev links agree, and reusable free indices are distinct/disjoint from live ones. Do not require meaningless endpoint links or free slots to be zeroed. Empty state resets size/map/free/head/tail as inspected. Postconditions: get hit returns current value and moves to MRU; miss preserves order; delete removes only selected key and reports prior presence; clear empties; new insertion beyond capacity removes oracle LRU; update keeps one key and moves it to MRU. Counterexamples: wrong eviction/return/size/order, duplicated/dangling live index, reused live free index or a cycle before reaching tail.
