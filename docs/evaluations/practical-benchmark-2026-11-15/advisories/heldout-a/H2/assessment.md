### O1 — Separate wildcard sender semantics from numeric identities

- **Priority/rationale:** P1 evidence lead. Unintended broad dispatch can invoke application receivers for unrelated senders. A minimal sequence is cheaper and more actionable than modeling all Python objects/GC. Actual incidence in downstream applications is unknown.
- **Target and boundary:** `r1:src/blinker/base.py:18` defines ANY as a Symbol and `r1:src/blinker/base.py:21` defines ANY_ID = 0. Signal.connect maps ANY to that ID and other senders through make_id (`r1:src/blinker/base.py:108`), then adds forward/reverse memberships (`r1:src/blinker/base.py:117`). `r1:src/blinker/_utilities.py:42` make_id returns str/int objects by value; Python bool is an int subtype and False compares equal to 0. Bound methods use a function/instance tuple; other objects use id. `r1:src/blinker/base.py:342` receivers_for unions the ANY_ID bucket with the sender bucket and yields each ID once. `r1:src/blinker/base.py:364` disconnect similarly maps sender and `_disconnect` treats ID 0 as disconnect-all (`r1:src/blinker/base.py:389`).
- **Caller/configuration closure:** send loops over receivers_for and calls receivers at `r1:src/blinker/base.py:238`; muting exits at `r1:src/blinker/base.py:230`. connected_to connects strongly then disconnects without sender at `r1:src/blinker/base.py:184`, making its cleanup broader than sender-specific disconnect; the intended restoration contract is unresolved. Receiver-connected/disconnected callbacks may reenter or raise; async wrappers, custom set_class and runtime weakref/GC implementations are not closed by this assessment. `r1:pyproject.toml:15` declares Python >=3.9 and `r1:pyproject.toml:75` names pytest testpaths, not verified runtime compatibility.
