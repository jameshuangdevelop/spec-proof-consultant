### O1 — Timer heap/ready-queue/reentrant callback state contract

- Priority: first in this slice. Cancellation/rearming during dispatch affects callback delivery and handle state. A finite abstraction could expose missed interleavings beyond examples, but correspondence effort is uncertain and greater than a small source dossier.
- Target/boundary: r1:src/timer.c:68–194 start/stop/again/run_timers; r1:src/uv-common.h:291–320 active/closing/start/stop macros, :348 initialization. Start/stop modify reference-counted active_handles; timer node overlays heap/queue storage. r1:src/heap-inl.h:109 `heap_insert`, :150 `heap_remove` maintain a pointer heap using comparator callbacks. Queue bodies unread (included at r1:src/uv-common.h:38); public timer structure uses UV_TIMER_PRIVATE_FIELDS at r1:include/uv.h:1018. Platform headers at :90/:97, timer_heap platform branch at r1:src/timer.c:28 and platform-loop/time/callback bodies prevent full closure. CMake requests C11 with extensions (:21–23), lists timer/common in uv_sources (:201–202) and branches on WIN32 (:206); configure.ac:37 requests gnu11 and contains platform-dependent linking. These are configuration observations, not compatibility results.
- Requirement: wakeup purpose **documented** at r1:include/uv.h:1012–1014; exact cancellation/rearm/order semantics **inferred** from timer.c, owner authority unconfirmed. Null callback/closing rejection and timeout saturation are source behavior. Equal-deadline FIFO intent is suggested by start_id comment (:50–53) but wraparound ordering and callback reentrancy promises are **unresolved**. No approval to establish or alter these contracts.
- Property: candidate abstract domain is a finite set of initialized live timers on one serialized loop, arbitrary uint64 time/timeout/repeat/start-counter values represented with a separately justified finite boundary partition or modular model, and callback actions stop/start/again/set_repeat on self or another timer. Preconditions: valid handles/loop/linkage and legal API calls, with closing states explicitly represented rather than assumed absent. Candidate invariant: at source transition boundaries a timer is not simultaneously heap-linked and ready-queue-linked; active timer heap membership and reference accounting agree; successful start schedules saturated time+timeout, failed null/closing start preserves timer state. During dispatch, only timers collected as due are queued, cancellation removes a pending ready entry, and nonzero repeat is rearmed before its callback. The currently popped callback is transiently neither pending-queue nor necessarily inactive; phase variables are needed, not an overstrong invariant. Counterexamples: callback after cancellation of its queued timer, duplicate membership/delivery, incorrect active-count change, early delivery, wrong saturation, or a claimed tie-order rule failing at counter wrap. Stop/start by callbacks and zero repeat must be included. Concurrent API mutation, invalid memory, platform scheduling and time refresh are unresolved boundaries, not silently approved domain exclusions.
- Method: candidate `tla-state-machine-safety` **1.0.0**, bundled `references/tlc.md`; compatibility **unknown**, separate model adoption pending. Conditional assurance exactly: “Invariant checking for the explored finite TLA+ model and recorded configuration, subject to constraints and complete exploration.” It does not establish original C correctness without correspondence, an unbounded theorem, memory safety, scheduler fairness or liveness. Catalog has no hard exclusion for this scenario, but that does not establish arbitrary abstraction compatibility. Pin TLC/TLA+ tools and Java, constants, arithmetic abstraction and phase actions before any execution.
- Alternatives: native stateful tests over legal API traces could sample real behavior after separate permission, without model-proof claims. Defer `tla-concurrency-liveness` 1.0.0: no approved progress/fairness requirement or scheduler closure. Do not select CBMC for the entire async timer loop: bundled CBMC scenarios hard-exclude concurrency, assembly and FFI, and callbacks/platform bodies are unread. An isolated arithmetic/heap investigation would require an actual supported boundary, not a success stub or rewritten toy that is claimed to verify timer.c.
- Dependencies/readiness: source dossier first, owner API/wrap/phase intent second, then model correspondence and adoption decision. Finite bounds are proposed model scope, not exclusions from the product contract. No implementation or execution authorized.
