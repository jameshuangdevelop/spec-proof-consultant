# Retained diagnostics — not altered gates

The prospective operational contract treats administrative read/accounting
deviations as diagnostics, unless an unchanged quality anchor or K1–K7 is
materially violated. These incidents are retained, not concealed waivers.
Independent findings and grades remain the single original evaluations.

## Campaign and delivery

- Protocol/development/confirmation report materialization initially encountered
  pointer/spill delivery failures. Retained canonical artifacts were
  materialized from the same original responses; no grading retry or favorable
  replacement was used. Raw runtime outputs are private, not public evidence.
- Pre-acquisition identity parsing expected `tree` but received `tree40`;
  mismatch occurred **before any Git/source acquisition**, then parser handling
  was corrected as data-only administration.
- Development `plutil` rejected valid JSON in a data-only probe. This did not
  change advisory content or grades. Development also records unavailable
  `python` metadata probing (exit 127) and an initially absent output directory.
- Confirmation's `python` metadata probe was unavailable (exit 127); available
  `python3` performed the same metadata purpose without target execution,
  installation, product repair or trial rerun.
- Mapper outputs were display-spooled by the tool/runtime. Complete-input and
  raw action accounting remain unavailable; display truncation is not evidence
  of zero additional input or of forbidden action.
- Parent arithmetic audit initially rejected a two-path invocation, then the
  data-only invocation was corrected. Heldout B's exact mean is a rational
  object `{"numerator":59,"denominator":6}`. The corrected data-only parser
  accepted it; **grade bytes were not changed** to fit a parser. No rounding
  before gates: A mean=79/8; B mean=59/6.
- Synthetic release-helper checking found a malformed second payload could
  cause partial release; prevalidation was fixed and checked before use.
  This is a trusted procedural-helper diagnostic, not target verification or
  evidence that base64 protects confidentiality.

Canonical author results and independent grade reports retain their available
command summaries, failed operations, coverage/window/metadata limitations and
source-backed findings. Retained materialization/packet digests in those reports
refer to original-private evidence, not newly normalized public bytes. These
diagnostics are not claims that all raw execution histories are published or
independently audited.

## Publication limitations

This package is documentation-only normalized evidence. Public primary pins,
license metadata and scope records are filtered data, not a new source audit.
The publication author did not read target bodies, execute/import target code,
run tests/builds/proofs/installations, acquire sources or use network.
All target implementation/testing/modeling proposals remain conditional on
requirements authority, correspondence, compatibility, actual owner grants and
appropriate execution isolation. A shared host/worktree/profile is not that
isolation. Tests, bounded checks, models and proofs remain distinct.

The initial publication metadata inventory was too broad: its JSON-key/size
probe parsed the two reserve identity documents as well as the six primary
ones. Only filenames, sizes and field names were displayed; no reserve identity
values were displayed or incorporated. This exceeded the requested read scope
and is disclosed for independent review, not self-excused by a privacy scan.
Subsequent publication filtering uses only primary records. No target bodies,
excluded-history file, raw maps or contributed helper code were read/executed.

The initial publication checker passed 462 checks but reported three failed
heldout-A advisory digest checks: it assumed an `assessment_sha256` field in
the grade identity, where that field is absent. The orchestrator subsequently
compared each original author's `canonical_artifacts` digest and byte count
with the original advisory bytes and the manifest's original/public hashes.
All three matched. The initial failed check report is retained; no advisory or
grade was changed, and this data-only reconciliation does not approve the
publication or excuse the metadata read-scope incident.

The default staged Git whitespace check flagged retained Markdown hard-break
spaces and blank terminal lines, including the byte-frozen quality rules.
Those evidence bytes were preserved. The scoped check disables only
`blank-at-eol` and `blank-at-eof`; this is not a claim that the default
whitespace check passed.
