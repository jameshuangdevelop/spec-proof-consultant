### Source observations

- The generic file and tests use `go1.18` build selection (`r1:btree_generic.go:15-21`, `r1:btree_generic_test.go:15-18`); the older implementation is `!go1.18` (`r1:btree.go:15-16`). Module declares Go 1.18 (`r1:go.mod:15-17`). Generic behavior is the selected boundary, not a proof of pre-generics parity.
- Clone assigns two fresh context pointers while initially sharing the root (`r1:btree_generic.go:613-634`, BTreeG.Clone). COW comments explicitly authorize writes only to matching contexts (`:594-607`); `mutableFor` copies item/child slices, not recursively the objects in T (`:235-253`); `mutableChild` rewrites the parent link (`:256-260`). This is structural isolation, not a deep object clone.
- Updates call `mutableFor` on the root and copy paths (`r1:btree_generic.go:686-744`, ReplaceOrInsert/deleteItem). Split and insert use the copied path (`:265-318`); deletion steals/merges through mutable children and may free the merged node (`:369-475`, remove/growChildAndRemove).
- `freeNode` clears only context-owned nodes, resets their context and offers them to the mutex-protected freelist (`r1:btree_generic.go:665-679`; `:100-123`, FreeListG). Clear(true) recursively resets but still delegates ownership rejection to freeNode; Clear(false) drops root/length (`:848-886`). A zero-capacity freelist is a meaningful full-pool case, not an error by itself.
- `find` treats comparator equivalence as equality and calls `sort.Search` (`r1:btree_generic.go:210-222`); LessFunc is a supplied function (`:590-592`), while Item explicitly requires strict weak ordering (`:73-79`). Comparators and item referents are not copied/frozen by Clone. Standard library sort, mutex, allocation/copy/append and GC are external trusted implementation boundaries here, not verified bodies.
- Same-tree writes are not safe concurrently (`r1:btree_generic.go:581-582`). Clone must finish before independent original/clone use (`:613-615`); freelist sharing alone is documented safe across trees (`:85-88`). No promise of concurrent Clone or concurrent writes to the same tree follows. Shallow item aliases can still create application races.
- Generic-backed legacy `BTree` delegates Clone, Delete and ReplaceOrInsert (`r1:btree_generic.go:900-1006`). `btree_mem.go:15-29` is an ignored executable with an external benchmark dependency, not a production COW callee; it was not run and is not an assurance artifact.

### O1 — P1: preserve untouched snapshots through clear/delete/reuse

- **Value/effort:** moderate test-only effort, high relevance to a downstream snapshot consumer. Existing randomized clone test does not by itself establish the specific mixed reclamation traces below. Small degrees and tiny freelists expose structural paths cheaply and deterministically; retain existing tests rather than replace them.
- **Requirement:** documented lazy structural isolation (`r1:btree_generic.go:613-623`) and map-like insert/delete results (`:681-724`), with Clear removal (`:848-868`). Proposed formalization is inferred; adopter must approve the acceptance contract for its use. No maintainer/adopter implementation grant exists.
- **Domain/preconditions:** well-formed trees constructed through NewG/NewWithFreeListG; stable deterministic comparator with strict weak ordering; no out-of-band mutation of ordering keys or comparator closure; distinct tree instances; serial Clone and serialized operations per instance. Concurrent distinct-tree use is retained as a separate schedule obligation, not disproved or proved by a serial pilot. Live references inside T remain shared; require immutable referents for a value-snapshot claim, or assert structural membership only. Use immutable integer/record values in the first test.
- **Exact pilot:** degree 2 or 3, freelist capacities 0, 1 and 2, up to three live trees/clones, keys 0..7, and records `(key,payload)` ordered solely by key so replacement of an equivalent key can be observed. Seed enough keys to split the degree-2 root. Follow Clone, independent ReplaceOrInsert, Delete (present/absent), DeleteMin/Max on empty/nonempty, Clear(false/true), clone-of-clone and reinsertion on either branch. Enumerate bounded operation traces up to an owner-approved length (suggest 8 after setup); record explored trace count, not “all trees.” This is useful stress of sharing/recycling, not all sizes/degrees/types.
- **Postconditions:** at Clone, both abstract maps equal the pre-clone map; only the selected branch's map changes on update. Replacement returns the prior representative/true without changing Len; new class returns zero/false and adds one; absent deletion returns zero/false without abstract-map change (internal topology may change). Successful deletion returns the prior item and reduces Len once. Clear makes only that tree empty. Get, Len and full Ascend agree with each branch's independent reference map after every operation. Empty Min/Max/DeleteMin/DeleteMax return zero/false.
- **State invariants:** ordered unique equivalence classes; Len equals cardinality; nonleaf child count equals items+1 (documented `r1:btree_generic.go:224-228`); nonroot occupancy `degree-1..2*degree-1`, balanced leaf depths; every node being mutated has the requesting context. Shared historical nodes are read-only to current contexts; pooled nodes are not reachable from any live root. Assertions may require test-internal traversal, not new production hooks.
- **Counterexamples:** clearing A or reusing its freed node alters B's traversal/Get; replacing `(k,p1)` with `(k,p2)` in A also replaces B's representative; an absent delete changes contents/Len; a live node appears in the freelist; a child is mutated with a mismatched context. A legal boundary trace is seed → clone → delete enough for root contraction in one branch → Clear(true) → reinsert while repeatedly checking untouched branches. This is a proposed challenge, not a reproduced bug.
- **Retained domain questions:** constructor rejects degree <=1, but maxItems uses `degree*2-1` (`r1:btree_generic.go:155-164`, `:638-645`). Extreme positive degrees/length overflow and allocation failure need separate intent/runtime analysis; pilot bounds do not certify every constructor-accepted degree. `Less[float]` includes floats (`:129-137`): NaNs cannot be silently assumed to satisfy the ordering obligation; confirm adopter type domain. The generic nil-panic comment (`:685`) is not established by a blanket generic nil check in the inspected method; resolve if nil-bearing T matters. None is a reason to change production in this assessment.
- **Method/limits:** noncatalog native stateful tests with an independently maintained reference map and focused ownership assertions. Possible later distinct-tree race-mode tests sample schedules only; no race mode was run. Actual toolchain/test compatibility remains untested. No native Go verification coverage is implied by the TLC guide.
- **Alternatives:** repeat the existing large clone test first only when execution is separately authorized; it provides baseline traces but not all mixed pool histories. Source review alone can validate ownership-path correspondence but not establish behavior over all traces. A whole-tree deductive port/replacement is not justified by adoption constraints.

### O2 — P2, optional: finite model of COW ownership and pool eligibility

- **Value/cost:** makes a subtle invariant reviewable independently of balancing code; higher correspondence cost and lower immediate benefit than O1. Only pursue if the adopter accepts a separate abstraction. Not a requested implementation today.
- **Requirement/domain:** inferred ownership safety formalizing the documented COW rule (`r1:btree_generic.go:594-607`) and observed freeNode guard (`:665-679`); owner approval missing. Suggested finite model: three tree handles, finitely bounded nodes and context tokens, pool capacity 0..2; no token reuse while reachable; initial well-formed tree and exclusive per-tree writer. Resource-exhausted transitions must be distinguished from actual Go allocation semantics, not mistaken for implementation deadlock.
- **Variables/transitions:** tree root/context, node owner/child links, live reachability and pool. Clone allocates *two* fresh contexts and shares historical roots; MutableFor either retains owned node or allocates/copies slice contents; mutableChild rewires one owned parent; Free rejects foreign-owned nodes or clears and pools owned ones; Clear visits descendants before dropping root. Links to `:235-260`, `:624-634`, `:665-679`, `:878-886` define correspondence obligations. Split/merge are not arbitrary safe “update” black boxes: either map their link/item moves (`:265-289`, `:437-474`) or explicitly leave balanced-tree correctness unclaimed.
- **Property:** always no pooled node reachable from any live root, no write to a mismatched-context node, and Clone prevents either new context from owning old shared nodes. Counterexample is a finite transition trace violating any conjunct, e.g. pooling a still-shared node after a clear. Initialization and every modeled transition must preserve the invariant. This is safety, not progress; no fairness or liveness claim.
- **Method:** `tla-state-machine-safety` v1.0.0, bundled `references/tlc.md`: “Invariant checking for the explored finite TLA+ model and recorded configuration, subject to constraints and complete exploration.” No catalog hard exclusion, but model/code correspondence and acceptance of abstraction are prerequisites; exact TLC/Java release compatibility unknown. It neither verifies the original Go code nor establishes unbounded ownership/race freedom.
- **Limits/alternatives:** serial logical operations omit low-level mutex schedules, memory races, allocation/GC, comparator side effects and full balancing semantics unless modeled. Review mutex boundaries separately before claiming any concurrent implementation correspondence. O1 hits real production; a model can miss a forgotten COW call in that production. Do not assume the desired invariant as an action precondition merely to make exploration pass.
