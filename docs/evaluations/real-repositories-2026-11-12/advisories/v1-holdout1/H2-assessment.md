## Decisions

One prioritized noncatalog opportunity: a small deterministic **logical snapshot and reclamation trace contract** for the downstream adopter's existing code. Do not rewrite the tree, port it into another language or claim “Go verification” from a language-independent model. Existing clone tests reduce the value of more large random insert/delete traces; small fork/clear/reuse and replacement traces have a more distinct diagnostic purpose.

### O1 — P1: COW isolation through rebalance, Clear and reuse

**Impact / effort / incremental value.** A reclaimed shared node or stale ownership token can corrupt another live snapshot. The ownership mechanism is compact, but split/merge/free-list interactions and clone chains make example-only evidence incomplete. A small same-package stateful test can check internals plus logical behavior and shrink a failing trace. Expected effort is modest relative to a proof or replacement, but actual missing coverage, downstream integration and test runtime remain unknown. No existing failure is alleged.

**Target and boundaries.** `BTreeG.Clone`, ReplaceOrInsert/Delete/DeleteMin/DeleteMax/Clear and the reached helpers above. No FFI, unsafe, assembly or async body was observed in those ranges. The uninspected standard Go allocation/GC, mutex implementation and `sort.Search` remain external library/runtime boundaries. The comparison function is an arbitrary callback: do not certify every user callback. Concurrency is real in the advertised separate-tree usage; a sequential pilot is not race freedom or validation of concurrent Clone.

**Intent and authority.**

- **Documented:** clone lazily shares structural nodes and subsequent writes use COW; current-node ownership must match the writer before mutation (`btree_generic.go:594-635`). Logical updates and their `(value, found)` results are described at `:681-745`; Clear removes all items at `:848-872`; node child-count invariant at `:223-228`.
- **Inferred proposal:** after every operation, untouched live trees retain their previous logical contents; a freelist node must not be reachable from any live root; B-tree ordering, occupancy and equal leaf depth remain valid; empty-tree and failed-delete results agree with the abstract map. These are candidate checks, not owner-approved stronger requirements.
- **Unresolved obligations:** the precise adopter value/comparator domain, pointer/payload mutation policy and downstream concurrency usage. `LessFunc` requests strict ordering (`:590-592`); `Item.Less` describes strict weak ordering/equivalence (`:72-80`). NaN-bearing float values via `Less[float64]`, stateful comparators and externally mutated keys cannot be silently included in a sorted-map guarantee. Structural cloning cannot promise payload deep copies: shared pointers remain shared. Resolve those domains, rather than assuming all T values/comparators are safe or labeling their behavior a COW bug.
- Approval: the campaign owner grants read-only advice only, not downstream requirement authority, test writes or execution. Archived-upstream status does not transfer approval to this assessor.

**Proposed precise contract.** For a valid constructed tree, stable comparison inducing the agreed strict weak order, stable key fields, and nonreentrant operations, model each tree as an independent map from comparator-equivalence class to the most recently inserted T. At Clone completion create a new logical map equal to the original. ReplaceOrInsert returns old representative/true if equivalent key existed, otherwise zero/false; only the selected tree changes. Delete returns and removes that representative or zero/false; min/max delete removes the corresponding class, returning zero/false on empty. Clear(true/false) makes just that tree empty. Len equals class count; Get/Min/Max and traversal (if added) match the map. All other live maps remain unchanged. After Clone, neither tree may write the old shared nodes in place; every write-path node must carry the writer's context. Returned T values themselves are ordinary shallow Go values; payload aliasing is not snapshot isolation.

A proposed finite native pilot uses degree 2 and 3, free-list capacity 0, 1 and default 32, at most three live trees, key set 0..7, and deterministic traces up to 24 operations. Use a value struct `{key, payload}` with comparison by key to distinguish replacement of an equivalent key from no-op integer replacement. Include clone-empty, clone-of-clone, writes to **both** branches, replacement at/after root split, Delete absent, DeleteMin/Max on empty, root shrink, left/right stealing and merging, then Clear(false), Clear(true) on shared and owned roots, reuse and another update while siblings remain live. Counterexamples are another live tree's map changing, wrong return flag/value/length, order/occupancy/child-count violation, a free node still reachable from a live root, or writing through the wrong context.

The structural invariants are root special occupancy; other nodes contain degree-1..2*degree-1 items, children count zero or items+1, in-order ranges separated by parent items, equal leaf depth, and no free-list/live-root overlap. Shared nodes across roots are legal; they need not carry either tree's **current** context until copied. Treating every reachable node as already writer-owned would wrongly reject legitimate lazy clones. The free list can be full or empty, and declining reclamation of an unowned node is legitimate. Clear(false) has no promise of immediate GC/reclamation.

These are proposed useful bounds, not a restriction on the production API. Larger degrees, trees, trace lengths, arbitrary T, allocation/resource failure, arithmetic overflow in huge degree, external payload mutation, and actual interleavings remain obligations outside the pilot. Same-tree concurrent mutation and concurrent Clone are outside the documented grant; separate-tree concurrent updates remain a separate required assurance question, not “proved” by sequential traces.

**Method.** Noncatalog native stateful/regression tests plus source-to-contract review, **not formal proof**. No catalog native-Go scenario is established. Use existing code; do not model rebalancing away and claim implementation coverage.

**Alternatives.** A later separate finite abstraction could match `tla-state-machine-safety` **1.0.0**, `references/tlc.md`: “Invariant checking for the explored finite TLA+ model and recorded configuration, subject to constraints and complete exploration.” Pattern fits ownership/reclamation transitions, not arbitrary Go verification. Such a model would need identities for nodes/contexts, branches, roots, free list and actual copy/free/split/merge transitions; a set-only map would miss the ownership hazard. Correspondence, finite configuration, owner acceptance of abstraction and tool compatibility are **unknown**, implementation blocked. The guide has no hard exclusion but does not confer automatic compatibility. Defer that higher-cost option unless tests/inspection leave a concrete invariant question.

Concurrent race testing after separate authorization could complement sequential checks on distinct cloned trees; it explores schedules rather than proving absence of races. `tla-concurrency-liveness` **1.0.0** is not justified for a fairness/progress guarantee: no such guarantee was found; a finite model cannot prove Go mutex/runtime fairness or implementation race freedom. Rust/C++ native catalog pilots and replacement/codegen are not fits to this Go code and no-replacement adoption goal.
